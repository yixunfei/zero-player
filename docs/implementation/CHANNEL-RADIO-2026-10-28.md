# 渠道、直播与广播增强

用户确认由当前会话顺序实施，清理均由用户点击确认执行。

## 实施方案

1. 内置 MaccmsResources 的 Site.json / R18.json；固定提交保存原文与许可；按接口身份去重，保留订阅归属和用户选择，补充 XML CMS 支持。
2. 探活区分成功、明确无效、超时/网络不确定、取消；当前批次完成后支持停用和移除。
3. 直播按节目频道识别常用别名，保留各来源线路和请求头；收藏、健康及清理持久化。
4. 广播保存成功订阅快照，内置可用列表以支持首次离线浏览；补充订阅管理与收藏。
5. 广播播放器由应用生命周期管理；切换页面和最小化继续播放，退出释放资源，切入视频时避免双重音频。用户补充确认 Windows 关闭窗口后驻留托盘：播放或连接广播时关闭窗口将隐藏，托盘提供显示窗口、暂停/继续、停止广播和明确退出；没有广播播放时沿用正常关闭。

## 完成内容

- MaccmsResources 原文保存在 `assets/catalogs/maccms`，固定提交 `e8ba0081d0ef7b4c6cc0c9c2a0de83226f0eb6db`，含来源记录和 MIT 许可。Site.json 19 条、R18.json 36 条，和原渠道按接口身份去重；支持 MacCMS JSON/XML。成人新增渠道默认停用。手动名称、请求头、启停和屏蔽选择保留，恢复内置使用实际持久 ID。
- 点播和直播探活均保留本批次结果并提供确认式停用/删除。明确错误才可清理，超时、网络异常、429/5xx、取消、未测完保持未确定。删除采用可恢复的持久移除，刷新不会自动复活。直播逐个原始来源探活，清理不影响同节目其他有效线路。
- CCTV 常用别名合并为节目视图，保留原始来源、收藏及对应线路请求头；5/5+、区域、4K 和不认识的后缀不混并。订阅改名刷新保持已保存偏好。
- 广播支持多个 M3U/TXT 订阅的增删、启停及刷新，按地址去重。成功列表同时保存到数据库与应用数据目录的 `radio_snapshots`；无效响应、空列表和失败更新不能覆盖快照，旧请求不能覆盖新结果。项目附带最后成功同步列表 `assets/catalogs/radio/cn.snapshot.json` 和显式同步脚本。
- 广播收藏独立持久化并进入备份；播放器归应用生命周期管理。切换页面继续播放，迷你播放器可控制；视频开始前暂停广播。连接中暂停或换台会退役旧播放器，超时后重试新建播放器。
- Windows 原生通知区域图标通过 `Shell_NotifyIconW` 实现。播放或连接广播时关窗驻留，托盘支持显示、暂停/继续、停止、退出。图标注册失败不隐藏窗口，Explorer 重建失败会恢复窗口，隐藏后停止仍保留返回入口。

## 使用与边界

操作见 [使用指南](USER-GUIDE.md#2026-10-28-渠道清理与广播后台播放)。清理必须由用户点击执行，不自动批量删除。探活有响应、目录解析成功和节目完整可播放是不同结论；未宣称所有公网渠道可播放。

本轮 Windows 托盘与本地媒体验证通过。Android 页面间播放沿用应用级控制器，但 Android 锁屏/系统后台服务与物理设备验收未包含；长期运行、所有公网源、干净 Windows 安装环境也未重新验收。未修改发布版本号、未自动提交已有工作区变更。
