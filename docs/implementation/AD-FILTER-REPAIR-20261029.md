# 广告回零与标记修复

日期：2026-10-29；当前工作区，本地构建标识 ad-repair-20261029，应用版本仍为 0.0.6+6。

## 本轮确认的缺陷

1. 默认音频模式：audioSimilarity 对静音返回零，完整样本评分把口播停顿作为不匹配，导致已通过校验的有效口播样本连自身都不能命中。先新增失败测试确认，再修复：停顿保留时序约束，不参与正向证据评分，至少四帧有效声纹仍须满足原有阈值；纯静音及不同停顿结构不会通过。
2. 保存样本只启动未来检测，没有应用当前影片已明确标记的区间；保存时样本已经播放，扫描起点又在当前时间之后，用户看不到任何跳过。现在同集按明确标记区间应用，其他作品仍要求实际特征匹配。
3. 采样从任意毫秒启动，与手动采集的 0.5 秒栅格错位。后台现在统一采样栅格并回看最长样本长度，避免刚保存的样本和边界片段被遗漏。
4. 一次采样异常会永久停止整场后台检测。改为单 worker、1–5 秒退避重试，连续失败后推进到当前播放点，暂停/取消仍停止采样。
5. 手动采样另开无清单过滤的网关，可能与实际播放时间轴不同。改为同一播放输入，明确转换 processed/original 坐标；跨被删除片段的样本拒绝采集。
6. 原 TS 修正要求 .ts 后缀和 discontinuity 标签。现按完整点播清单及实际传输字节识别；无后缀、伪后缀及漏标断点的 TS 都可处理。首次保存开启过滤时会在原位置重开，避免仍沿用未修正输入。

- Windows 原生：带 discontinuity 的归零 TS 和无后缀/无 discontinuity 的归零 TS 均连续播放；规则强制改为不同作品，验证真正指纹命中，而非本集区间跳过代替匹配。

## 验证范围

已确认用户运行上一轮 player-improvements 便携版，但当前会话读取到的应用库没有观看/特征记录；用户尚未提供具体渠道与影片。因此这些是已复现的软件缺陷修复，不是对用户实际渠道广告识别率的承诺。新增播放诊断用于确认真实输入类型和残余问题，未启用自动上传或持久化敏感播放日志。

加密 HLS、fMP4、字节区间、多路音视频、直播及单段内部不规则重置仍不做 TS 字节改写，诊断会显示覆盖边界。流畅播放优先；后台识别可能晚于内容播放。此轮针对 Windows 便携版交付，Android 不宣称实机验证。

## 截图中的采集失败：mark-repair-20261029

用户截图显示在 355.0–359.5 秒采集“音频相似”，校验异常使“保存并应用”不可用。旧提示把声音单一、静音和采集不完整混为一谈，而本集时间区间也被特征校验阻断。

本轮调整：

- “仅保存本集区间”独立于特征采集，失败或采集中也可保存。应用已有的来源/作品/线路/剧集绑定、时长校验、片段管理、启停和撤销；明确开启全局及该作品的自动跳过。该操作不生成跨集特征，也不要求启用音频识别。
- 起止时间和前后偏移决定实际区间，超出片尾的后偏移截到总时长。处于区间内且正在播放时立即跳过；暂停时保持暂停，恢复后应用；已经过区间则不强行回退。保存不会暂停或重开视频。
- 音频失败可点“改用画面并采集”，保留当前时间范围和偏移；预览成功后才允许保存复用特征。静音、单音及不完整证据仍拒绝，未降低匹配阈值、未补造声纹。
- 分开报告音频/画面不完整（实际/应有帧数）与信息量不足，界面不再暴露 FormatException 前缀；播放诊断记录本集区间数及采集模式、时间、帧数或错误原因，不记录媒体地址和样本。
- 标记窗口绑定打开时的播放代次；切集、切换渠道、重开后拒绝旧窗口写入当前影片。既有特征修改保持原匹配类型，避免改模式后沿用不相容的指纹。
- 后台初始化和手动采样在关闭时等待结束，修复全量测试中暴露的临时目录删除竞态。横屏大字体时操作按钮换行，正文可滚动。

复现结论：原生有效口播的 4.5 秒样本，以及模拟 355.0–359.5 秒样本均完整取得 18 个音频帧。因此不能把截图错误直接归因于 4 秒加 0.5 秒的分段；保持原采样算法。合成单音复现了相同的校验失败，并验证上述恢复流程。实际渠道和媒体输入仍未获得，无法断言用户该样本属于静音、单音还是缺帧，也不能宣称其“回零→广告→恢复”已完全消除。

验证记录：全量单元/组件测试 407 通过、2 个原有网络测试跳过；flutter analyze 无问题，源码/函数规模检查通过。8 个 Windows 原生场景通过：音频失败后直接保存及撤销/重播、改用画面保存、355 秒处 4.5 秒与静音/缺失/短音轨采样、切源拒绝旧标记、取消采集继续播放、音频跨集真实命中、带标签归零 TS、无后缀无标签归零 TS。测试使用本机合成素材，未访问用户实际渠道。
