# v0.0.3 直播管理与搜索

用户确认单击选中、双击 / Enter / 播放按钮播放；既有改动一并验收提交。元数据仅取现有订阅、播放清单和节目表；缺失标记未知，直播无固定时长。

## 行为与边界

- 单击、焦点移动、菜单操作均不会启动播放器；宽屏操作面板直接提供播放与停用，窄屏保留详情、停用和播放按钮。
- 检测明确不可用自动停用；超时、限流、服务器暂忙、未测完备用线路为未确定，保留原启停状态。管理菜单和检测结果支持一键停用未确定项。
- 一键检测已停用频道仅恢复收到媒体响应的来源，不复活已移除项；取消不写失败结果。全量检测覆盖已停用项，恢复启用属于独立操作。
- 分类、语言、地区来自发布者明确字段，清单分辨率和音轨语言只属于实际选中的 HLS 视频变体，不能把音频 rendition 当成视频。检测结果与 URL 签名绑定，线路变化使旧结果失效。
- 按分类、语言、分辨率细分筛选；文本搜索包括名称、来源和已有元数据。未确定、已停用、有媒体响应分组独立可见。不同来源的属性在详情中分开查看。
- 自动读取 M3U 声明的 XMLTV 地址，保留手动地址；节目单最多显示 48 条后续节目，时长由结束时间减开始时间。缺少 tvg-id 时只用既有频道别名规则做唯一匹配；冲突、地区版本或不匹配项保持未知，并显示匹配方式与节目表来源。多来源节目表支持失败回退。
- 当前浏览来源传入搜索，优先调度并优先排列同名结果；可切换仅当前来源。停用、移除和成人过滤规则照常生效。
- 搜索展示完成进度、每源耗时、失败 / 未完成来源重试；重试保留其他来源结果，取消保留部分结果，历史及时刷新，旧请求不得覆盖新搜索。每源最多 5 页并明确标注。
- 直播数据库刷新按相关表监听并合并到 250 ms；搜索分组排序在通知间缓存。

## 审查复现

先用 `tool/backup_database.py` 对用户库备份，再在独立审查数据库运行 `tool/audit_live.dart`。订阅抓取与媒体探测分开记录，媒体阶段逐项追加 JSONL，可按 ID 与 URL 签名断点续查。探测只经现有生产 HTTP 安全边界；每来源最多 3 条线路，每路 256 KiB、8 秒实际网络预算，维护审查并发 16，每 origin 最多 4 个请求；应用内检测仍为并发 2。

`tool/finalize_live_audit.py` 拒绝不完整结果，生成随包快照；仅匹配相同 ID 和 URL 的新条目使用该快照，既有个人选择不被导入覆盖。`tool/apply_live_audit.dart` 在应用关闭和备份完成后应用本次审查，保留收藏、历史、设置及已有订阅选择。

检测中的 ms 是到首媒体数据的时间，不是 ICMP Ping，也不证明完整解码或持续播放。IPv6 / 网络超时不能据此认定永久失效。安全边界和 Windows DLL 生命周期修复沿用 v0.0.2，详见 HARDENING-2026-10-28.md。

节目表实测：5 个声明 URL，3 个超时、1 个返回 HTTP 403，1 个有效（543 个节目频道标识）。该有效订阅未填写 tvg-id，按严格唯一别名核验可关联 35 个频道来源，其他缺失与歧义不猜测。有效数据保存在审查库，应用审查时仅复制当前订阅使用的同一 URL 缓存。
