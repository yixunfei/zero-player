# 跳转、续播与特征管理修复

构建标识：`feature-seek-sync-20261029`；应用版本仍为 `0.0.6+6`。

## 已复现原因

1. 后台收到显式 seek 后，仍接收旧位置的原生状态。回归测试请求跳至 600 秒，再发送 0 秒旧状态，旧实现实际采样 0 秒。播放器层也会在 seek 等待期间应用旧位置标记。
2. 历史续播在总时长未就绪时保留 `_resume`，但旧路径仍将 0 秒状态交给新建检测会话。自动检测跳过则绕过后台 seek，检测和播放不共用位置变化。
3. 长标记只回看一个锚点长度。真实 AAC 口播测试从下一集 310.5 秒续播时，重复口播被循环次序优先选为较晚起点，原本应到 319.137 秒的跳过延长到了 326.850 秒。
4. 管理中的每次修改分别调用单次密码授权，缺少限定在管理窗口生命周期内的授权。

## 实现

- 所有主动跳转统一发出检测取消与重定位。播放器确认目标位置前不应用旧状态；快速跳转串行执行原生命令，丢弃已被新目标取代的排队请求。首次命令即时发出，保持方向键响应。
- 新会话在异步创建结束后读取最新目标；续播时长未就绪时不向检测传送片头进度。原生命令完成但位置迟迟未确认时，三秒后按实际播放器位置重新同步；失败也恢复跟随。
- 后台独立保留待确认目标、取消旧 probe、清空旧重试退避并重置时序指纹。暂停时不启动新采样；用户重播会重新匹配，撤销跳过仍保留本次观看权限。
- 多锚点规则回看最长锚点的两倍（不超过标记时长）；综合全部锚点证据后按时间选择有支持的边界，仍要求两个不同锚点的偏移一致，不降低匹配阈值。
- 新增窗口持有的 `SensitiveSession`，只授权 settings 操作，不保留密码、不解锁全局；窗口关闭或监管配置变化后失效。独立编辑入口仍按原权限检查。

- `dart analyze` 无问题；源码/函数大小检查通过。
- 新原生用例 `feature_seek_resume_native_test.dart` 使用真实 FFmpeg AAC 44.1 kHz 双声道和 MediaKit：原集标记 5–21 秒，下一集内容移至 303.137–319.137 秒。从 310.5 秒续播，暂停拖至 301 秒重播，连续跳至 10/335/309 秒，以及同频道另一作品从 301 秒续播，均命中内容并跳至约 319.150 秒。新作品/新集 `originKey` 不同，没有本集固定区间捷径。
