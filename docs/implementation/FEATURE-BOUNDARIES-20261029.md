# 长片段采集、关键词确认与跨集匹配修复

日期：2026-10-29。应用版本保持 0.0.6+6，诊断标识 `feature-boundaries-20261029`。

## 确认后的行为

- 关键词与用户特征同时检测；关键词、OCR/语音文字判定均先确认。保守和积极自动策略只作用于用户内容特征。
- 标记范围支持 1 秒至 10 分钟。范围不再等于识别样本长度，内部最多采集 12 个带相对偏移的短特征。长片段至少保留两个有效样本，多个样本在新位置的偏移一致才推算完整跳过边界。
- 起止时间使用分:秒或时:分:秒，支持毫秒、精确秒数输入和当前播放时间按钮。采集不再向外扩大到 0.5 秒网格。样本内部可按采样精度裁短，但用户确认的完整边界不变。
- 快速标记默认不在片段末尾额外加 20 秒。设置中的默认 20 秒仍用于关键词确认跳过建议，特征的前后扩展由用户明确设置。已有规则的偏移不自动修改。

## 实现与错误处理

- `FeatureAnchor` 表示实际采到的短样本；`FeatureRule.sampleMs` 表示完整标记时长。既有短规则保留原数据读取路径，不删除用户特征。
- 单次采集不足时按真实完整帧保留至少 1 秒且具有辨识度的样本，不补零、不复制帧；低质量或解码失败的窗口明确计数。无有效样本仍拒绝生成复用规则。
- 首部短样本连续安排，其余样本覆盖长片段。后台匹配只需短样本缓存，按候选位置减去样本偏移计算整段起点，静音停顿结构继续校验。
- 结果通过 `FilterDetection` 保留来源；`FilterDetectionQueue` 统一处理优先级。关键词不能扩展已确认内容特征的边界，忽略关键词不会屏蔽后续手动特征命中。
- 后台单 worker 每次处理后最少间隔 400 ms，不再额外等待等长处理时间。继续遵守暂停、缓冲、取消与退避重试。
- 扫描进度单独展示在管理/诊断中，不反复触发播放器 3 秒提示。已播过的结果记录为过期，不跳过后续正常内容。

## 验证依据与边界

- 新增真实 Windows 测试：选择 16 秒片段，移动 3.137 秒，改变音量并重编码为 AAC 44.1 kHz 双声道 64 kbps。全剧与同频道不同作品均以内容命中，跳过 8.15–24.15 秒；无原始集固定区间、无外部模型。
- 真实短音轨测试：选择 4.5 秒但音轨提前结束，保留实际短样本且完整边界仍为 4.5 秒；静音仍拒绝。355 秒处采集、无音轨改画面、取消采集和切源失效均验证。
- 旧双路 FFmpeg 参数与新参数在当前有效素材上都得到 4000 ms 音频，未复现旧帧数上限截断，不能把它声明为用户实际音频缺失的根因。
- 用户实际媒体未提供。当前回归证明本地素材上的规则加载、解码和跨集匹配链路；不能证明所有频道的编码、网络和内容差异都可匹配。基础指纹仍依赖重复内容，不能理解未知广告，也不能撤回已经播放的内容。
- 先前失败采集或“仅保存本集区间”不会自动变成跨集规则；需要在新版本中选完整片段重新提取并保存。
