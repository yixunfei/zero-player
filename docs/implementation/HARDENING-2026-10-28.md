> 本文保留 2026-10-28 的历史验收结果。2026-10-29 新增明确的局域网服务授权，并继续加固输入与凭据边界；当前行为见 [渠道源安全加固记录](SOURCE-SECURITY-2026-10-29.md)。

日期：2026-10-28（Asia/Shanghai）。用户确认 Windows 范围，既有未提交的渠道、电台和界面改动一起接手、验收和提交。

## 退出与资源释放

在旧版便携程序上实际点击标题栏关闭，数分钟后窗口和进程仍存在。原退出链逐个无限等待异步清理，一个未完成 Future 即可阻止 native destroy。新增单个资源默认 2 秒上限；桌面保存/钩子各 2 秒，服务清理总等待 8 秒；系统退出请求最多等待服务 10 秒。清理异常仍尝试后续步骤，重复关闭保持幂等。超时只停止等待，不等同于取消所有原生操作；最终桌面窗口退出负责结束进程。

保留既有广播后台播放行为：广播播放时关闭窗口进入托盘，托盘“退出”执行完整关闭。闲置或视频场景关闭窗口直接退出。

首次正式包验收进一步发现系统退出入口冲突：Flutter 的 `didRequestAppExit` 先调用服务清理，移除了窗口监听，但 `window_manager` 的 preventClose 仍然开启，后续关闭被拦截且无人处理。系统退出现在统一委托 `DesktopLifecycle.closeWindow` 完成保存、清理和 native destroy，并取消框架重复退出；广播则沿同一路径隐藏到托盘。新增 3 项路由回归，原生托盘测试改为发送真实窗口关闭消息，避免直接调用 Dart 关闭方法掩盖问题。首次失败包已记录并备份数据库后终止，没有作为通过验收的结果。

随后通过进程退出码和 Windows 错误事件捕获到原生销毁阶段的访问冲突。`WM_QUIT` 路径现在在 COM 与 C++ 成员析构前显式执行 `window.Destroy()`，`FlutterWindow` 析构也先进入幂等销毁，避免销毁过程中的窗口消息访问已部分释放的 Flutter 控制器。修复后 Release 全屏 Alt+F4 实测正常退出（退出码 0，约 756 ms）；原生托盘关闭回归再次通过。

普通窗口复验还捕获到媒体库卸载竞态。仅保留 winpthreads 仍不足：崩溃转储显示后台线程在 `pthread_mutex_lock+5` 访问 `0x77f950d0`，该地址属于已卸载的 `libffmpegkit.dll`（基址 `0x77ef0000`）。插件析构直接 FreeLibrary，库的进程级回调线程尚在等待条件变量。Windows runner 因此对已经加载的 `libffmpegkit.dll` 设置进程期保留，同时保持其依赖和静态数据有效，不加载任何新路径。仍执行应用清理、引擎销毁与正常进程退出，没有用强杀掩盖错误；失败验收记录保留在 build 日志中。

旧进程退出失败后，先通过 SQLite backup API 保存 `artifacts/user-backups/before-hardening-20261028.sqlite`（integrity_check=ok），再结束已核实路径的旧进程。

## 安全边界

- 来源只作为数据解析，不增加网页容器、浏览器跳转或远程 Spider/JAR/JS/Python 执行能力。
- 网络只允许 HTTP(S)，拒绝凭据和控制字符；每次实际建连检查 DNS 返回地址，禁止回环、私网、链路本地、组播、IPv4 映射/过渡地址等目标。连接固定到已经检查的 IP，HTTPS 仍使用原域名进行 SNI 和系统证书验证。重定向也经过相同检查。
- 不采用未校验的代理目标；来源不能通过 Host、Connection、Transfer-Encoding 或换行请求头改变路由/构造请求。跨域凭据沿用原有精确 origin 隔离。
- 视频和广播均使用受控媒体网关；HLS 子资源改写到有随机令牌的回环 URL。回环网关检查 Host，并拒绝 Origin/Sec-Fetch-Site 浏览器请求，响应添加 nosniff 和禁止主动内容的 CSP。
- 原生播放器禁用配置、自动脚本、危险播放列表、自动字幕/音轨加载；普通媒体禁止外部引用。只有网关或离线服务当前登记的 HLS 清单允许分片引用，并强制 HLS 解复用器；切回普通媒体立即收回权限。写入后回读选项，未生效则拒绝打开。解码器协议不包含 file、data、udp、rtp、concat 等。
- HLS URI 属性必须能被完整改写；未加引号或未知标准扩展中的资源引用拒绝处理。实验室页面也始终走受控网关，开关只控制缓存，避免直连绕过网络边界。
- 单媒体通过 add/loadfile 加载，消除 media_kit.open 的临时本地播放列表；应用仍负责选集/换源。网页、脚本、XML/JSON、可执行文件与未受控播放列表在媒体路径被拦截；Range 中段不误按文件开头识别。
- FFmpeg 完整解码与 FFprobe 检查限定 mov/mpegts 容器和 file 协议；导出按本地文件或回环输入分开协议范围。Windows 从 DLL 搜索中排除当前工作目录，减少旁加载风险，保留 Dart 原生资产所需的标准加载行为。

这些是应用层纵深防护，并非操作系统级沙箱。mpv/FFmpeg 仍解析第三方二进制媒体，不能承诺原生解码器绝无漏洞。自定义 LAN/localhost 来源当前在生产网络层拒绝；测试夹具权限不进入正式启动配置。

## 性能

播放状态通知以 50 ms 窗口合并，减少同一轮多流事件触发的重复组件刷新；关闭 mpv 冗余磁盘缓存，保留有配额的应用分片缓存。单媒体加载不再创建临时播放列表。来源 API 探测预算 25 秒，失败后不再额外访问首页抓名称；并发限制保持 1–6，播放保留网络配额。

本机合成样本的 14 项缓存/不缓存原生播放测试：首帧 499–654 ms，平均 571 ms，网关错误均为 0。覆盖 MP4、FLV、TS HLS、fMP4、AES-128、ByteRange、分离音轨的解码、暂停、拖动和倍速。广播安全测试最近一次启动至进度推进 657 ms，切换 HLS 再切回广播后的释放为 2 ms（此前冷路径样本 209 ms）。这些是本机样本，没有据此宣称公网提速比例。

## 渠道策略

检测成功自动启用；明确失败或超时/网络不确定暂时停用，保留记录；后台对停用且未移除的渠道持续复检，恢复成功后自动启用。已移除/重复归档项不会被后台复活。手动批量、单渠道与后台检测采用同一策略。成人内容显示仍由现有内容过滤设置决定。

本次从内置和用户库合并检测 124 个来源；修复 TLS 后进行完整核查，再以 25 秒 API 预算复查 91 个不确定项，最终为 25 个接口可用、22 个失败、77 个不确定、0 个确认域名不存在。结果只反映本机当次 DNS/TCP/API，不能替代媒体播放验证。看剧AI、555电影和360资源站均成功。无效的第一轮 TLS 适配结果已被重新核查覆盖，没有应用到用户数据库。

首页频道、设置默认频道及管理卡片显示 TCP 建连耗时，详情/提示包含检测时间。该数值是 TCP Ping，不是 ICMP 或视频质量评级。

已应用至用户数据库：124 条记录全部保留，23 个可见启用、93 个可见停用、8 个重复归档。25 个 API 成功项中有 2 个属于既有重复归档，因此不重新加入选择器。SQLite 完整性为 ok；前后逐表摘要只在 sources、source_overrides、source_health、app_meta 改变，历史、下载、直播、设置等其他表逐行一致。
