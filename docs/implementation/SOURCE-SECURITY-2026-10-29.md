# 渠道源执行边界与数据保护加固

日期：2026-10-29（Asia/Shanghai）。本轮按用户确认的顺序检查源导入、网络请求与重定向、原生播放/探测、日志和凭据；保留由用户明确授权的局域网媒体服务。

## 已修复的路径

### 1. 不可信内容进入播放器和 FFmpeg

- `native_input_policy.dart` 统一校验原生播放入口：仅接受本进程当前登记、没有额外查询或片段的 HTTP 回环资源。未登记地址不能直接进入 mpv；普通公网地址必须先交给受控网关。
- 保留并回读校验 mpv 的脚本、配置、自动字幕/音轨和外部引用限制。只有已登记、重写后的 HLS 清单临时开放必要引用并强制 HLS 解复用器，切回普通媒体立即收回。
- FFprobe、帧/声音采样和导出增加格式白名单；只有登记为 HLS 的输入才开放 HLS 格式并强制使用对应解复用器。原生输入仍受协议白名单约束。
- 本轮没有增加远程 JS、Python、JAR、Spider 执行能力；网站播放器配置仍按数据解析。

### 2. HLS 变量与资源属性注入

- 查询参数、继承变量等替换值中的换行、控制字符和引号会被拒绝，阻断变量展开后新增清单行或属性的路径。
- 限制变量值 8192 字符、单行 65536 字符、最多 40000 行和展开总长 2 MiB；多属性替换也计入单行预算。
- 解析阶段统一验证 URI 属性，拒绝未加引号、重复、未知标准扩展资源属性及危险协议。离线下载与在线播放采用相同检查，避免仅在网关重写时才检查。普通厂商注释保持惰性文本。
- 已有特殊 key 声明的解析行为保留；能解析声明不等于原生协议白名单放行，也不新增 DRM 支持。

### 3. 伪造 Content-Range 绕过媒体检查

- 原先仅凭响应的非零 `Content-Range` 就可能跳过文件头检查。现在只有实际请求了相符的中段范围或后缀范围，才采用中段读取路径。
- 无对应范围请求、范围起点不匹配或格式不正确的响应仍检查内容前缀，防止将网页、脚本、可执行文件或未受控播放列表伪装成中段媒体。
- 网关直通和缓存相关响应路径均使用同一判定。

### 4. 凭据和诊断数据泄露

- 修复直播订阅请求头被继承到清单中任意播放地址的问题。频道从所属订阅的原始地址获得请求头作用域；同源保留经过净化的请求头，跨源只保留 User-Agent 和净化后的公开 Referer。Authorization、Cookie、自定义设备标识等不会随跨源频道转发。既有数据库记录读取时同样受保护。
- HTTP 跨源重定向不携带原站凭据；不建立服务端响应 Cookie 的自动追踪会话。
- 网站解析生成的 Referer 去除查询、片段和用户凭据；跨源仅发送站点根地址，HTTPS 降级不发送。
- 新请求诊断隐藏 URL 路径和全部查询值，移除用户凭据与片段；自定义请求头默认隐藏，仅保留有限的协议诊断字段。主机、参数名和部分诊断字段仍可见。既有已持久化诊断记录没有批量改写。
- `.local`、`.lan`、`.home`、`.home.arpa`、`.internal` 等内部名称不发送给公网 DNS 确认服务，包含大小写及尾点处理。

## 局域网授权

入口为“设置 → 局域网访问授权 → 添加授权”。输入例如 `http://192.168.1.10:8080`，检查地址后还需确认授权；监管模式按现有敏感设置规则验证。

- 授权精确匹配协议、IP 和端口，覆盖该服务下的路径；最多 32 项。支持 RFC1918 IPv4 和 IPv6 ULA。
- 不接受域名、通配符、路径、查询、用户凭据、本机回环、链路本地或云元数据地址。需要不同协议或端口的服务必须分别配置。
- 授权只保存在本机，不从渠道配置或个人备份导入；备份伪造授权记录会被拒绝。
- 每次请求重新核验，即使连接被复用或资源已进入网关缓存。修改授权关闭当前网络连接；撤销后新请求被拒绝，已经下载或进入播放器缓冲的字节不会被追回。
- HTTP 跨源重定向及沿原清单作用域请求的跨源 HLS 子资源不能借用授权，即使目标服务也在授权列表中。同源 HLS 分片正常使用。
- 授权是对应用访问该媒体服务的许可，**不是完整的逐渠道来源追踪或逐路径许可**。部分海报、节目表、解析结果等上层流程会建立新的请求作用域。因此只应授权专用媒体服务，不应授权路由器后台、凭据服务或其他管理接口；来自不同渠道的元数据不能被视为独立隔离的安全主体。

实现分为 `lan_access_policy.dart`（地址分类）、`lan_access_store.dart`（本机授权持久化/串行修改）、`lan_access_dialog.dart`（用户确认）和既有网络策略执行层。授权在启动网络任务前加载。授权存储关闭时仅等待真实的待完成修改，避免空队列在组件测试的虚拟时钟中悬挂。

## 保证范围

本轮验证的是可构造的不安全输入及其拦截行为，没有认定某个真实公网渠道已被植入木马，也不提供“来源无毒”认证。请求头隔离、网关和格式白名单是应用层防护，不能替代操作系统沙箱或修复原生解码器自身漏洞。此次没有升级 mpv/FFmpeg 原生库。

资源提供方仍能看到连接 IP、请求时间和播放所必需的资源地址；用户主动交给同源服务的凭据仍会发送给该服务。元数据请求及本地备份仍可能包含用户信息，不应将本轮改动解释为匿名播放或全面日志清洗。

本轮没有 Android 实机验收，没有构建发布包、提交或推送，也没有操作真实用户数据库。测试均使用夹具或临时数据。后续如需声称跨平台原生行为一致，应补做相应设备验证。
